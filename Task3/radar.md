# Технологический радар

Радар показывает предлагаемые решения на начало перехода компании.

Значение колец:

- **Adopt** — продолжаем использовать.
- **Trial** — проверили пользу на небольшой реальной задаче.
- **Assess** — изучаем и проверяем.
- **Hold** — поддерживаем существующие решения, но не используем в новых задачах.

Кольцо Trial пока пустое: сначала нужны результаты пилотов.

| Технология | Квадрант | Кольцо | Состояние | Для чего нужна |
|---|---|---|---|---|
| Python | Языки | Adopt | Используется | Развитие ИИ-сервисов |
| Go и Java | Языки | Adopt | Используется | Развитие финтех-продуктов |
| PowerBuilder | Языки | Hold | Используется | Поддержка текущей системы клиник |

| Apache Camel | Инструменты | Hold | Используется | Поддержка старых интеграций |
| Yandex Cloud IaaS | Платформы | Assess | Предлагается | Отдельные ресурсы для доменов |
| Terraform | Инструменты | Assess | Предлагается | Повторяемое создание ВМ, диска и сети |

Архитектор вместе с представителями доменов и платформы пересматривает радар раз в квартал. Во время пилота результаты новых инструментов рассматриваются ежемесячно.

Для перехода из Assess в Trial нужен опыт работы на реальной задаче. Для перехода в Adopt проверяем эксплуатацию, права, восстановление и затраты. Технологии в Hold продолжают работать до готовности замены.

В первом квартале проверяем Terraform и публикацию данных на тестовых наборах. Для Lakehouse измеряем стоимость и время типовых запросов. Если результат не устроит, сохраняем подготовленные витрины без обязательного перехода всех направлений на Iceberg.
