# Домены и потоки данных

| Домен | Ответственная команда | За что отвечает и какие данные передаёт | Зачем выделен |
|---|---|---|---|
| Клиники | Команда медицинской системы | Приём, персонал, инвентаризация. Набор «Работа клиник»: период, клиника, загрузка и выручка без медицинских данных | Медицинские процессы можно менять независимо от финтеха |
| Финтех | Банковская команда | Счета, платежи, кредиты. Набор «Финансовые показатели» по организациям и периодам | Банковские правила и обновления развиваются отдельно |
| ИИ-сервисы | Команда ИИ | Обработка медицинских данных через закрытый API. Набор «Работа ИИ»: число запросов, задержки и ошибки | Можно отдельно менять модели и вычислительные ресурсы |
| Фармацевтика | Команда партнёра и ответственный за интеграцию | Планируемый обмен данными о поставках и остатках. Отчётность по товарам и периодам | Партнёр подключается через согласованный контракт |
| Электроника | Команда партнёра и ответственный за интеграцию | Планируемый обмен данными об устройствах, поставках и техническом состоянии без сведений о пациентах | Новые типы оборудования подключаются отдельно |
| Корпоративная аналитика | Команда данных головного офиса | Общие определения показателей, сводные отчёты и портал | Головной офис получает общую картину бизнеса |

Платформенная команда поддерживает общие инструменты. Команды доменов отвечают за расчёты, смысл и качество своих данных. Общие правила доступа и качества согласуют представители доменов, команда данных и информационная безопасность.

На DFD сплошные стрелки показывают существующие направления обмена, пунктирные — планируемые подключения партнёров.

Клиника передаёт ИИ необходимые медицинские данные через закрытый API и получает результат. Эти данные используются для работы медицинского сервиса и не попадают в отчётность.

Для оплаты клиника передаёт финтеху реквизиты счёта и сумму. Финтех возвращает статус оплаты. Диагноз для этого обмена не требуется.

Каждый домен готовит свой продукт данных, проверяет поля и качество, затем сохраняет набор в своей области хранения. В DataHub передаются описание, схема, владелец и происхождение данных — lineage. Dremio читает разрешённые наборы, Power BI строит отчёты. Права на просмотр карточки и чтение самих данных проверяются отдельно.

В контракте данных указываются:

- версия схемы и состав полей;
- смысл показателей и владелец;
- частота обновления;
- правила доступа;
- проверки качества.

Для пилота предлагаем обновление управленческих данных раз в час. Это цель, которую ещё нужно проверить.

Перед публикацией проверяем обязательные поля, типы, дубли и контрольные суммы показателей. Изменения схемы согласуем заранее. Старую версию сохраняем на время перехода.

Для сводных отчётов используем общие ключи организации, периода и продукта. Персональные сведения о пациентах для них не нужны. Перед объединением одноимённых показателей проверяем, что они имеют одинаковый смысл.

Data Mesh внедряем постепенно: сначала назначаем владельцев и согласуем контракты, затем запускаем каталог и пилот, после этого подключаем остальные направления. Домены используют общую платформу. Адаптеры к DWH и Camel сохраняются до проверки замены.
