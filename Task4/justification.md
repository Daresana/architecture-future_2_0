# Обоснование конфигурации

Это небольшая учебная среда IaaS в Yandex Cloud. Она показывает, как Terraform создаёт связанные ресурсы. Полная платформа из Task1 здесь не разворачивается.

Terraform создаёт пять ресурсов: сеть, подсеть `10.11.0.0/24`, группу безопасности, загрузочный SSD и ВМ. Образ Ubuntu 22.04 получает через `data`.

Выбраны 2 vCPU и 4 ГБ памяти для проверки доступа и небольшого тестового сервиса. Для совместного запуска DataHub, Dremio и Airflow этих ресурсов недостаточно. Их размеры нужно рассчитывать отдельно.

SSD на 10 ГБ нужен для ОС и небольших тестовых файлов. Образу Ubuntu требуется минимум 8 ГБ. Выбранный размер укладывается в квоту учебного аккаунта — 10 ГБ SSD на зону. Диск и ВМ находятся в одной зоне.

Публичный IP задаётся через NAT в сетевом интерфейсе ВМ. Он нужен для SSH и загрузки обновлений. SSH-порт 22 открыт только для одного адреса администратора с маской `/32`. Порты приложений закрыты. При расчёте стоимости учитываются ВМ, диск и внешний IP.

Перед запуском вручную подготавливаются облако, платёжный аккаунт, каталог, права и SSH-ключ. ОС и приложение настраиваются отдельно. Отказоустойчивость и резервные копии предусмотрены в плане рабочей системы.

Токен хранится в переменной окружения `YC_TOKEN`. Облако и каталог задаются через `YC_CLOUD_ID` и `YC_FOLDER_ID`.

В `terraform.tfvars` указаны размеры ресурсов. Перед `plan` нужно передать свои значения `admin_cidr` и `ssh_public_key`. Закрытый SSH-ключ остаётся вне проекта.

В файлах описано нужное состояние инфраструктуры. Это декларативный подход. По ссылкам между ресурсами Terraform определяет порядок создания: сначала сеть для подсети, затем ВМ с нужными диском, подсетью и группой безопасности.

Эти же файлы можно использовать для повторного создания инфраструктуры. Размеры ресурсов меняются через параметры. Автомасштабирование нужно добавлять отдельно.

Порядок проверки: `init → validate → plan → apply`. Файл состояния `state` хранит идентификаторы объектов и не публикуется. Откат конфигурации не восстанавливает удалённые данные, поэтому изменения проверяются через `plan`.

05.11.2026 выполнены `init`, `fmt -check`, `validate`, `plan` и `apply` с Terraform 1.13.5. Созданы пять ресурсов. Скриншот сохранён в `apply.jpg`. После проверки выполнен `destroy`: все пять учебных ресурсов удалены, исходные ресурсы сохранились.
